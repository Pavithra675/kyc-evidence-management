# KYC Evidence & Review Management System – Data Dictionary

## 1. Overview

This document describes the database entities, important fields, and relationships used in the KYC Evidence & Review Management System.

The database uses SQLite and SQLAlchemy ORM.

## 2. Database Entities

### 2.1 Customer Types

Stores the types of customers supported by the system.

| Field | Description |
|---|---|
| customer_type_id | Unique customer type identifier |
| type_name | Customer category, such as Individual or Business |

### 2.2 Customers

Stores customer onboarding information.

| Field | Description |
|---|---|
| customer_id | Unique customer identifier |
| customer_type_id | Reference to the customer type |
| full_name | Customer's full name |
| email | Customer email address |
| onboarding_status | Current onboarding status |
| created_at | Customer creation timestamp |

### 2.3 KYC Requirements

Defines mandatory and optional evidence requirements for each customer type.

| Field | Description |
|---|---|
| requirement_id | Unique requirement identifier |
| customer_type_id | Associated customer type |
| document_type | Required document category |
| risk_level | Risk level associated with the requirement |
| is_mandatory | Indicates whether the document is mandatory |

### 2.4 Documents

Stores customer KYC evidence details.

| Field | Description |
|---|---|
| document_id | Unique document identifier |
| customer_id | Associated customer |
| document_type | Type of submitted document |
| issue_date | Document issue date |
| expiry_date | Document expiry date, if applicable |
| document_status | Current document status |
| holder_name | Name appearing on the document |

### 2.5 Verifications

Tracks document verification outcomes.

| Field | Description |
|---|---|
| verification_id | Unique verification identifier |
| document_id | Associated document |
| verification_status | Verification result |
| verified_at | Date and time of verification |
| reviewer | Person or reviewer responsible |

### 2.6 Risk Ratings

Stores customer risk assessment results.

| Field | Description |
|---|---|
| risk_id | Unique risk assessment identifier |
| customer_id | Associated customer |
| risk_level | Assigned customer risk category |
| risk_score | Numerical risk score |
| assessed_at | Risk assessment timestamp |

### 2.7 Review Cases

Tracks periodic customer KYC reviews.

| Field | Description |
|---|---|
| review_id | Unique review identifier |
| customer_id | Associated customer |
| review_date | Review date |
| due_date | Review completion deadline |
| review_status | Current review status |
| resolution | Review outcome or resolution details |

### 2.8 Beneficial Owners

Stores ownership information for business customers.

| Field | Description |
|---|---|
| owner_id | Unique beneficial owner identifier |
| customer_id | Associated business customer |
| owner_name | Beneficial owner's name |
| ownership_percentage | Percentage of business ownership |

### 2.9 Alerts

Stores alerts generated by the system.

| Field | Description |
|---|---|
| alert_id | Unique alert identifier |
| customer_id | Associated customer |
| alert_type | Category of alert |
| alert_message | Description of the alert |
| created_at | Alert creation timestamp |
| alert_status | Current alert status |

### 2.10 Audit Events

Maintains a record of important system activities and changes.

| Field | Description |
|---|---|
| event_id | Unique audit event identifier |
| entity_type | Type of entity affected |
| entity_id | Identifier of the affected entity |
| event_type | Type of activity performed |
| old_value | Previous value, if applicable |
| new_value | Updated value, if applicable |
| reason | Reason for the change |
| actor | Person or process performing the activity |
| created_at | Event timestamp |

## 3. Entity Relationships

- One CustomerType can be associated with multiple Customers.
- One CustomerType can have multiple KYCRequirements.
- One Customer can have multiple Documents.
- One Document can have multiple Verification records.
- One Customer can have one RiskRating.
- One Customer can have multiple ReviewCases.
- One Customer can have multiple BeneficialOwners.
- One Customer can have multiple Alerts.
- AuditEvents record activities across different entities.

## 4. Important Business Rules

1. Every document must reference an existing customer.
2. Mandatory KYC evidence depends on customer type.
3. Expired documents must be identified even if marked as verified.
4. Approved customers should have all mandatory evidence.
5. Total beneficial ownership should not exceed 100%.
6. Closed review cases should have a resolution.
7. Duplicate evidence should be identified for investigation.
8. Overdue open reviews should be flagged.

## 5. Data Quality Scenarios

The synthetic dataset includes deliberately introduced scenarios to test validation:

- Expired but verified documents.
- Approved customers missing mandatory evidence.
- Ownership percentages exceeding 100%.
- Closed reviews without resolutions.
- Potential duplicate documents.
- Overdue open reviews.

All generated records are synthetic and intended for testing and demonstration.
